# RC1 Benchmark Evidence

RC1 is the release-candidate evidence bundle for the WAM context selector. It is
generated by a single command and produces a self-describing artifact set with
content hashes, so any published number can be traced back to the run that
produced it.

## Generate

```bash
npm run report:rc1
# or
node benchmarks/reports/generate-rc1.mjs
```

Write the bundle somewhere else:

```bash
node benchmarks/reports/generate-rc1.mjs --out=/tmp/rc1
```

Only one flag exists: `--out=<dir>`. There are no hidden flags; passing anything
else is ignored.

## Artifacts

The bundle is written to `benchmarks/reports/rc1/` by default.

| File              | Contents                                                                    |
| ----------------- | --------------------------------------------------------------------------- |
| `manifest.json`   | `sha256` + byte count of the other five artifacts, generation timestamp       |
| `raw.json`        | Verbatim inputs: the validation summary and the real-suite report            |
| `metrics.json`    | The three separated metric blocks                                            |
| `comparison.json` | Internal-vs-empirical notes and any `INVALID_COMPARISON` markers              |
| `evidence.json`   | The external evidence corpus projection, with the cache caveat               |
| `report.md`       | Human-readable report with three separate sections                          |

## The three sections

The report **never** merges the three evidence classes into one figure. This is
a hard constraint of the generator, asserted by
`benchmarks/reporters/rc1-report.test.mjs`.

### A. Internal Deterministic

From `benchmarks/run-validation.mjs`. No network; every input is a local
deterministic model. Covers snapshot correctness, fast-path hits, rebuild
avoidance, and deterministic accounting.

### B. Empirical Real (dry-run)

From `benchmarks/run-real.mjs` via `runDryRun()`. Uses the in-file mock provider,
so **no network call is ever made**. Reports input tokens, total tokens, rebuilds,
outcome equivalence (`outcomeMatch` / evaluated), and a per-scenario multi-turn
breakdown. Runs whose baseline/WAM pairing lacks token accounting are flagged
`INVALID_COMPARISON` rather than silently averaged.

### C. External Evidence

From `benchmarks/evidence/sources.json`. These are **mechanism precedents**, not
measurements of WAM. They are listed so a reader can see the surrounding design
space (prompt caching, context compression, agent context cost).

## Why internal and empirical can disagree

The deterministic suite and the dry-run suite are different harnesses over
different models. In the shipped dry-run configuration, the mock provider's WAM
overhead **exceeds** the baseline context, so `netInputSavings` is negative while
the validation suite reports a positive reduction percentage.

That is not a contradiction and is not smoothed over. `comparison.json` records an
`INVALID_COMPARISON` issue explaining that the two harnesses measure different
things, and the report states that no single net-savings number is claimed.

## Reproduce end to end

```bash
# 1. suites (writes a uniform envelope per suite)
node benchmarks/cli.mjs --suite=deterministic --out=/tmp/rc1-run
node benchmarks/cli.mjs --suite=validation    --out=/tmp/rc1-run
node benchmarks/cli.mjs --suite=real          --out=/tmp/rc1-run
# or all three
node benchmarks/cli.mjs --suite=all --out=/tmp/rc1-run

# 2. report
node benchmarks/reports/generate-rc1.mjs --out=/tmp/rc1-report

# 3. verify hashes
node -e "const m=require('/tmp/rc1-report/manifest.json');console.log(m.artifacts)"
```

## Verify the code

```bash
node --test benchmarks/evidence/evidence.test.mjs \
         benchmarks/reporters/rc1-report.test.mjs \
         benchmarks/cli.test.mjs
```

See also `docs/benchmark/methodology.md` and `docs/benchmark/limitations.md`.
